VLANs & Network Segmentation

Separate IoT, management, and trusted devices for security. Configure on managed switches and router for defense in depth.

Intermediate ~25 min read Updated 2026

Why Network Segmentation?

Contain Breaches

If IoT device is compromised, attacker can't easily reach management network or trusted devices.

Reduce Broadcast Domain

Less broadcast traffic per segment. Better performance, easier troubleshooting.

Policy Enforcement

Firewall rules between VLANs. IoT can't initiate connections to management. Guest isolated from everything.

Compliance & Organization

Clear network topology. Easier auditing. Logical grouping by function, not physical location.

VLAN Planning

VLAN ID Name Subnet Purpose Access Policy
1 MGMT 10.10.10.0/24 Network gear, hypervisors, management IPs Admin only, no internet
10 SERVERS 10.10.10.0/24 Docker hosts, VMs, NAS, services Inter-VLAN to clients, limited internet
20 TRUSTED 10.10.20.0/24 Personal devices, laptops, phones Full internet, access to servers
30 IOT 10.10.30.0/24 Smart home devices, cameras, sensors No internet initiation, no inter-VLAN
40 GUEST 10.10.40.0/24 Visitor devices Internet only, completely isolated
50 VPN 10.10.50.0/24 WireGuard/Tailscale clients Access to management & servers
Tip: Use consistent VLAN IDs across all switches. Document your scheme. Reserve IDs 100+ for future expansion (DMZ, lab, etc.).

Managed Switch Configuration

Port Types

  • Access Port: Single VLAN, untagged. End devices (PCs, APs, cameras).
  • Trunk Port: Multiple VLANs, tagged. Uplinks, router, hypervisors, APs with multiple SSIDs.
  • Hybrid Port: One untagged (native) + tagged VLANs. Rarely needed.

Example: TP-Link / Omada / Generic CLI

# Create VLANs
vlan 10
 name SERVERS
vlan 20
 name TRUSTED
vlan 30
 name IOT
vlan 40
 name GUEST

# Configure access ports (end devices)
interface gigabitethernet 1/0/1
 description "NAS"
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast

interface gigabitethernet 1/0/5
 description "Living Room AP"
 switchport mode access
 switchport access vlan 20

# Configure trunk port (uplink to router)
interface gigabitethernet 1/0/24
 description "Uplink to Router"
 switchport mode trunk
 switchport trunk allowed vlan 1,10,20,30,40,50
 switchport trunk native vlan 1

UniFi Switch (via Controller UI)

  1. Settings → Networks → Create New Network for each VLAN
  2. Set VLAN ID, subnet, DHCP (or none for MGMT)
  3. Port Manager → Select ports → Assign Network Profile
  4. Uplink port: Set to "All" (trunk) or specific VLANs
  5. AP ports: Trunk with all WiFi VLANs

Router / Gateway Configuration (OPNsense / pfSense)

Create VLAN Interfaces

# OPNsense: Interfaces → Other Types → VLAN
# Parent: Physical interface (e.g., igb0)
# VLAN Tag: 10, 20, 30, 40, 50
# Name: SERVERS, TRUSTED, IOT, GUEST, VPN

DHCP Server per VLAN

  • Services → DHCPv4 → [VLAN Interface]
  • Enable, set range (e.g., 10.10.10.100-199)
  • DNS: Point to Pi-hole/AdGuard (on SERVERS VLAN)
  • Gateway: VLAN interface IP

Firewall Rules (Top-Down Processing)

Interface Action Source Destination Description
MGMT Pass MGMT net Any Management can reach all
SERVERS Pass SERVERS net TRUSTED, VPN Services to clients
SERVERS Block SERVERS net IOT, GUEST No access to untrusted
TRUSTED Pass TRUSTED net SERVERS, MGMT, VPN Clients to services
TRUSTED Pass TRUSTED net Any (WAN) Internet access
IOT Pass IOT net DNS (Pi-hole) DNS resolution only
IOT Block IOT net RFC1918 (all LAN) No inter-VLAN access
IOT Pass IOT net WAN (specific) Allow NTP, updates only
GUEST Pass GUEST net WAN Internet only
GUEST Block GUEST net RFC1918 No LAN access
VPN Pass VPN net MGMT, SERVERS, TRUSTED Remote admin access
Important: Always create a "Allow established/related" rule at top. Put explicit blocks before "allow all" rules. Test from each VLAN before locking down.

WiFi VLAN Mapping (UniFi / OpenWrt)

UniFi Controller

  1. Settings → WiFi → Create SSID per VLAN
  2. "Trusted WiFi" → VLAN 20 (TRUSTED)
  3. "IoT WiFi" → VLAN 30 (IOT) - 2.4GHz only
  4. "Guest WiFi" → VLAN 40 (GUEST) - Enable Guest Policy
  5. AP port on switch: Trunk with VLANs 20,30,40 tagged

OpenWrt (/etc/config/wireless)

config wifi-iface 'trusted'
    option device 'radio0'
    option network 'trusted'
    option mode 'ap'
    option ssid 'Home-Trusted'
    option encryption 'psk2+ccmp'
    option key 'your-password'
    option vlan '20'

config wifi-iface 'iot'
    option device 'radio0'
    option network 'iot'
    option mode 'ap'
    option ssid 'Home-IoT'
    option encryption 'psk2+ccmp'
    option key 'iot-password'
    option vlan '30'

Inter-VLAN Routing Options

Option 1: Router-on-a-Stick (Single Interface)

One physical link from router to switch (trunk). Router does all inter-VLAN routing.

Pros: Simple, single cable
Cons: All traffic through router (bottleneck), single point of failure

Option 2: Layer 3 Switch (Recommended for 10G+)

Switch has routing capability. Traffic between VLANs stays on switch backplane.

# Enable routing
ip routing

# Create SVIs (Switch Virtual Interfaces)
interface vlan 10
 ip address 10.10.10.1 255.255.255.0
interface vlan 20
 ip address 10.10.20.1 255.255.255.0
# ... repeat for each VLAN

# Default route to firewall
ip route 0.0.0.0 0.0.0.0 10.10.1.1  # Firewall IP

Option 3: Separate Router + L3 Switch

L3 switch for high-speed inter-VLAN, firewall for WAN/VPN/edge policies.

Testing & Validation

  1. Ping gateway from each VLAN: ping 10.10.10.1
  2. Ping across VLANs (should work per firewall rules)
  3. Test blocked paths: ping 10.10.30.10 from TRUSTED (should fail)
  4. Verify internet: curl https://1.1.1.1
  5. Check DNS: nslookup google.com 10.10.10.5 (Pi-hole)
  6. Test WiFi: Connect to each SSID, verify correct IP/VLAN

Verification Commands

# On router/firewall
arp -a | grep 10.10.30   # Verify IOT devices got correct IPs

# On switch
show mac address-table dynamic | grep vlan 30
show interfaces trunk

# Packet capture
tcpdump -i vlan30 -n port 53  # DNS traffic on IOT VLAN

Troubleshooting

Devices can't get DHCP

# Check VLAN interface up on router
# Verify DHCP server enabled on that interface
# Check switch port: correct VLAN, not trunk
# Trunk port: allowed VLANs includes this VLAN
# Native VLAN mismatch on trunk

Can ping gateway but not internet

# Check outbound NAT rules on firewall
# Verify WAN interface has valid IP
# Check DNS resolution (try 8.8.8.8 directly)
# Firewall rule: allow VLAN net to WAN

Inter-VLAN not working

# Check firewall rules on SOURCE interface
# Rules processed top-down, first match wins
# Verify no "block RFC1918" rule above allow rule
# Check state table: pfctl -ss | grep 10.10

WiFi clients on wrong VLAN

# AP switch port must be trunk with all SSID VLANs tagged
# Verify SSID → VLAN mapping in controller
# Check RADIUS/VLAN attributes if using Enterprise auth

mDNS/Chromecast not crossing VLANs

# Install avahi-daemon / mdns-repeater on router
# Or use UDP reflector (port 5353)
# UniFi: Settings → Networks → Enable mDNS Reflection
