Docker Fundamentals

Master the core concepts of Docker - containers, images, volumes, networks, and Docker Compose. The foundation for running all your self-hosted services.

Beginner ~25 min read Updated 2026

What is Docker?

Docker is a platform that packages applications and their dependencies into standardized units called containers. Unlike virtual machines, containers share the host OS kernel, making them lightweight, fast to start, and portable across environments.

Why Docker for home labs? Every service (Jellyfin, Nextcloud, Home Assistant) runs in its own isolated container with its own dependencies. No dependency conflicts, easy updates, and simple backups.

VMs vs Containers

Aspect Virtual Machines Containers
Isolation Hardware-level (full OS) Process-level (shared kernel)
Startup time Minutes Seconds
Resource overhead High (GBs RAM) Low (MBs RAM)
Portability Limited High (run anywhere)
Density Few per host Dozens per host

Core Concepts

Understanding these four concepts is essential for working with Docker effectively:

Images

Read-only templates containing application code, libraries, dependencies, and runtime. Built from a Dockerfile. Identified by name:tag (e.g., jellyfin/jellyfin:10.10.7).

Containers

Running instances of images. Each container has its own filesystem, networking, and process space. Ephemeral by default - changes are lost on removal unless using volumes.

Volumes

Persistent storage managed by Docker. Survive container recreation. Preferred over bind mounts for portability. Can be named or anonymous.

Networks

Enable communication between containers. Bridge (default), host, overlay, and macvlan drivers. Containers on same network reach each other by service name.

Images vs Containers

Image Layers

Docker images are built in layers. Each instruction in a Dockerfile creates a layer. Layers are cached and shared between images, making builds fast and storage efficient.

# View image layers
docker history jellyfin/jellyfin:10.10.7

# Inspect image details
docker inspect jellyfin/jellyfin:10.10.7

Container Lifecycle

# Create container (not started)
docker create --name my-jellyfin jellyfin/jellyfin:10.10.7

# Start container
docker start my-jellyfin

# Run = create + start (most common)
docker run -d --name my-jellyfin jellyfin/jellyfin:10.10.7

# Stop container (SIGTERM, then SIGKILL after 10s)
docker stop my-jellyfin

# Restart
docker restart my-jellyfin

# Remove (must be stopped first)
docker rm my-jellyfin

# Force remove running container
docker rm -f my-jellyfin

Naming & Tagging

Never use :latest in production. It's a mutable tag that changes. Always pin specific versions: jellyfin/jellyfin:10.10.7. This prevents surprise breaking changes during updates.

Building Images with Dockerfile

A Dockerfile is a text file with instructions to build a custom image. Most home lab users won't write Dockerfiles (using upstream images), but understanding them helps with debugging.

Common Instructions

# Base image
FROM ubuntu:24.04

# Metadata
LABEL maintainer="you@example.com"
LABEL description="Custom Jellyfin with hardware transcoding"

# Install dependencies
RUN apt-get update && apt-get install -y \
    intel-media-va-driver-non-free \
    && rm -rf /var/lib/apt/lists/*

# Create non-root user
RUN useradd -m -u 1000 jellyfin
USER jellyfin

# Set working directory
WORKDIR /app

# Copy files
COPY --chown=jellyfin:jellyfin . .

# Expose port (documentation only)
EXPOSE 8096

# Default command
CMD ["jellyfin"]

Build & Tag

# Build with tag
docker build -t my-jellyfin:10.10.7 .

# Build with build args
docker build --build-arg JELLYFIN_VERSION=10.10.7 -t my-jellyfin:10.10.7 .

# Multi-platform build (for ARM + x86)
docker buildx build --platform linux/amd64,linux/arm64 -t my-jellyfin:10.10.7 --push .

Persistent Data with Volumes

Containers are ephemeral. When you remove a container, its writable layer is deleted. Volumes provide persistent storage managed by Docker.

Named Volumes (Recommended)

# Create volume
docker volume create jellyfin-config
docker volume create jellyfin-metadata

# Use in docker run
docker run -d \
  --name jellyfin \
  -v jellyfin-config:/config \
  -v jellyfin-metadata:/data \
  -v /mnt/media:/media:ro \
  jellyfin/jellyfin:10.10.7

# List volumes
docker volume ls

# Inspect volume
docker volume inspect jellyfin-config

# Backup volume
docker run --rm -v jellyfin-config:/data -v $(pwd):/backup alpine tar czf /backup/jellyfin-config.tar.gz -C /data .

# Remove unused volumes
docker volume prune

Bind Mounts

Map a specific host path to container path. Useful for config files you edit directly, or media libraries.

# Bind mount syntax: -v /host/path:/container/path
docker run -d \
  -v /home/user/jellyfin/config:/config \
  -v /mnt/media:/media:ro \
  jellyfin/jellyfin:10.10.7
Feature Named Volumes Bind Mounts
Portability High (Docker manages path) Low (host-dependent path)
Direct file access Via container only Direct on host
Backup/Restore Easy with docker commands Standard file tools
Best for App data, databases, configs Media files, editable configs

Container Networking

Network Drivers

  • bridge (default) - Containers on same bridge network can communicate by name. Isolated from host network.
  • host - Container shares host network stack. No port mapping needed. Less isolation.
  • macvlan - Container gets its own MAC/IP on physical network. Appears as separate device.
  • none - No networking. Complete isolation.

Custom Bridge Networks (Best Practice)

# Create custom network
docker network create --driver bridge homelab

# Attach containers to network
docker run -d --name jellyfin --network homelab jellyfin/jellyfin:10.10.7
docker run -d --name nginx --network homelab nginx:alpine

# Containers resolve each other by name: http://jellyfin:8096
docker exec nginx wget -qO- http://jellyfin:8096

Port Publishing

# Publish port 8096 on host to 8096 in container
-p 8096:8096

# Publish on specific interface only
-p 127.0.0.1:8096:8096

# Publish UDP
-p 53:53/udp

# Random host port
-p 8096

Docker Compose for Multi-Container Apps

Docker Compose defines and runs multi-container applications using a YAML file. The standard for home lab deployments.

docker-compose.yml Structure

version: '3.8'

services:
  jellyfin:
    image: jellyfin/jellyfin:10.10.7
    container_name: jellyfin
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - jellyfin-config:/config
      - jellyfin-metadata:/data
      - /mnt/media:/media:ro
    ports:
      - "8096:8096"
    environment:
      - TZ=America/New_York
    # Hardware transcoding (Intel Quick Sync)
    devices:
      - /dev/dri:/dev/dri

  nginx:
    image: nginx:alpine
    container_name: nginx-proxy
    restart: unless-stopped
    networks:
      - homelab
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certs:/etc/letsencrypt:ro
    depends_on:
      - jellyfin

networks:
  homelab:
    driver: bridge

volumes:
  jellyfin-config:
  jellyfin-metadata:

Key Compose Commands

# Start all services (detached)
docker compose up -d

# View logs (follow)
docker compose logs -f jellyfin

# Stop all services
docker compose down

# Stop and remove volumes
docker compose down -v

# Pull latest images
docker compose pull

# Recreate with new images
docker compose up -d --force-recreate

# Validate config
docker compose config

Environment Variables & .env File

# .env file (not committed to git)
TZ=America/New_York
JELLYFIN_VERSION=10.10.7
MEDIA_PATH=/mnt/media
services:
  jellyfin:
    image: jellyfin/jellyfin:${JELLYFIN_VERSION}
    environment:
      - TZ=${TZ}
    volumes:
      - ${MEDIA_PATH}:/media:ro

Best Practices

✅ Use Specific Tags

image: jellyfin/jellyfin:10.10.7 not :latest. Predictable, reproducible deployments.

✅ Restart Policies

restart: unless-stopped - Auto-restart on crash, boot, or Docker daemon restart. Not on manual stop.

✅ Non-Root Users

Run containers as non-root. Use user: "1000:1000" or ensure upstream image uses non-root.

✅ Resource Limits

Prevent one container from starving others: deploy: resources: limits: memory: 2G

✅ Health Checks

Define health checks so Docker knows if service is actually working, not just running.

✅ Read-Only Root FS

read_only: true + tmpfs for writable dirs. Prevents container filesystem modification.

✅ Secrets Management

Never hardcode passwords. Use secrets: in Compose or Docker secrets. Or env file (less secure).

✅ Version Control Compose Files

Keep docker-compose.yml and .env in git. Infrastructure as code.

Complete Production-Ready Example

version: '3.8'

services:
  jellyfin:
    image: jellyfin/jellyfin:10.10.7
    container_name: jellyfin
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - jellyfin-config:/config
      - jellyfin-metadata:/data
      - /mnt/media:/media:ro
    environment:
      - TZ=${TZ}
      - JELLYFIN_PublishedServerUrl=https://jellyfin.example.com
    devices:
      - /dev/dri:/dev/dri
    healthcheck:
      test: ["CMD-SHELL", "curl -f http://localhost:8096/health || exit 1"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s
    deploy:
      resources:
        limits:
          memory: 4G
        reservations:
          memory: 1G
    read_only: true
    tmpfs:
      - /tmp
      - /var/cache/jellyfin
    security_opt:
      - no-new-privileges:true

networks:
  homelab:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16

volumes:
  jellyfin-config:
  jellyfin-metadata:

Common Commands & Troubleshooting

Essential Daily Commands

# List running containers
docker ps

# List all containers (including stopped)
docker ps -a

# View logs
docker logs -f jellyfin
docker logs --tail 100 jellyfin

# Execute command in running container
docker exec -it jellyfin bash

# View resource usage
docker stats

# View container processes
docker top jellyfin

# Inspect container (network, mounts, config)
docker inspect jellyfin

Cleanup Commands

# Remove stopped containers
docker container prune

# Remove unused images
docker image prune -a

# Remove unused volumes
docker volume prune

# Remove unused networks
docker network prune

# Nuclear option - remove EVERYTHING unused
docker system prune -a --volumes

Common Issues & Fixes

Port already in use

Error: port 8096 already allocated

# Find what's using the port
sudo lsof -i :8096
# Or use different host port
-p 8097:8096

Permission denied on volumes

Container can't read/write bind mount

# Fix ownership on host
sudo chown -R 1000:1000 /path/to/config
# Or run container with matching UID/GID
--user 1000:1000

Container exits immediately

Check logs for error

docker logs jellyfin
# Common: missing config, wrong permissions, port conflict

Out of disk space

Docker images/volumes consuming disk

docker system df
docker system prune -a --volumes

Network connectivity issues

Containers can't reach each other

# Verify same network
docker network inspect homelab
# Test DNS resolution
docker exec jellyfin nslookup nginx

Image pull fails

Registry rate limits or auth required

# Authenticate
docker login ghcr.io
# Or use mirror
# Increase rate limit with authenticated pulls
