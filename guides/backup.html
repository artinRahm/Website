Backup Strategy

Implement the 3-2-1 backup rule with automated backups for all your services. Protect your data from hardware failure, ransomware, and human error.

Intermediate ~30 min read Updated 2026

The 3-2-1 Backup Rule

The gold standard for data protection:

3

Three Copies

Original + 2 backups. One primary, two redundant copies.

2

Two Media Types

Different storage media (e.g., local SSD + external HDD + cloud). Protects against media-specific failures.

1

One Offsite

At least one copy in a different physical location. Protects against fire, theft, ransomware, natural disasters.

RAID is not a backup. RAID protects against drive failure only. It doesn't protect against deletion, corruption, ransomware, fire, or controller failure. You need actual backups.

What to Back Up

Critical (Must Have)

  • Docker volumes - App data, databases, configs (Jellyfin metadata, Nextcloud data, Home Assistant config)
  • Docker Compose files - Your infrastructure as code
  • .env files - Secrets, passwords, API keys
  • SSL certificates - Let's Encrypt certs from NPM
  • SSH keys - Server access keys
  • Password manager vault - If self-hosted (Vaultwarden)

Important (Should Have)

  • Media libraries - If you can't easily re-acquire (personal photos, home videos)
  • Configuration files - /etc, custom nginx configs, scripts
  • Monitoring data - Grafana dashboards, Prometheus data (optional)

Optional (Nice to Have)

  • Downloaded media - Movies, TV shows (can re-download, but slow)
  • Container images - Can re-pull from registries
  • OS / system files - Reinstall OS, restore configs instead

Backup Tools Comparison

Tool Type Encryption Deduplication Cloud Support UI Best For
Borgmatic/Borg Config-driven ✅ AES-256 ✅ Excellent Via rclone/rsh ❌ CLI only Linux servers, efficiency
Restic CLI ✅ AES-256 ✅ Good ✅ Native (S3, B2, etc.) ❌ CLI only Cross-platform, cloud-native
Duplicati Web UI ✅ AES-256 ✅ Good ✅ Many providers ✅ Web UI GUI preference, Windows
UrBackup Client/Server ✅ Optional ✅ Good ❌ Local only ✅ Web UI Client backups (PCs/laptops)
rsync + cron Manual scripting ❌ Manual ❌ None ❌ Manual ❌ CLI Simple local mirrors
My recommendation: Borgmatic + BorgBackup for local + rclone to cloud, or Restic for native cloud support. Both are battle-tested, encrypted, and deduplicated.

Borgmatic + BorgBackup

BorgBackup (borg) is a deduplicating, compressing, encrypting backup tool. Borgmatic wraps it with declarative YAML config and scheduling.

Installation

# Ubuntu/Debian
sudo apt install -y borgbackup borgmatic

# Or via pipx (recommended for latest)
pipx install borgmatic

# Verify
borgmatic --version
borg --version

Configuration (config.yaml)

# /etc/borgmatic/config.yaml or ~/.config/borgmatic/config.yaml
location:
    source_directories:
        - /home/user/docker           # Compose files, .env
        - /var/lib/docker/volumes     # Docker volumes
        - /etc/letsencrypt            # SSL certs
        - /root/.ssh                  # SSH keys
    repositories:
        - path: /mnt/backup/borg-repo
          label: local
        - path: rclone:remote:borg-repo
          label: cloud
    exclude_patterns:
        - '*/cache/*'
        - '*/tmp/*'
        - '*/logs/*.log'
        - '*.pyc'
        - '__pycache__'
    exclude_if_present: .nobackup

storage:
    encryption_passphrase: "your-strong-passphrase-here"
    # Or use keyfile: encryption_keyfile: /path/to/keyfile

retention:
    keep_daily: 7
    keep_weekly: 4
    keep_monthly: 6
    keep_yearly: 2
    prefix: "backup-"

consistency:
    checks:
        - name: repository
        - name: archives
          frequency: 2 weeks
    check_last: 3

hooks:
    before_backup:
        - echo "Starting backup at $(date)"
    after_backup:
        - echo "Backup completed at $(date)"
    on_error:
        - echo "Backup failed at $(date)" | mail -s "Backup Failed" admin@example.com

Initialize Repository

# Local repository
borgmatic init --encryption repokey --repository /mnt/backup/borg-repo

# Cloud via rclone (configure rclone first)
borgmatic init --encryption repokey --repository rclone:remote:borg-repo

Run Backups

# Manual run
borgmatic --verbosity 1 --files

# Dry run
borgmatic --dry-run --verbosity 1

# With systemd timer (automatic)
sudo systemctl enable --now borgmatic.timer

# Check timer status
systemctl list-timers | grep borgmatic

Prune & Compact

# Prune old backups per retention policy
borgmatic prune --verbosity 1

# Compact repository (reclaim space from deleted data)
borgmatic compact --verbosity 1

Restic + Rclone

Restic is a modern, fast, encrypted backup tool with native support for many cloud providers. Rclone handles the cloud transport.

Installation

# Ubuntu/Debian
sudo apt install -y restic rclone

# Or download latest binaries
# https://github.com/restic/restic/releases
# https://rclone.org/downloads/

Rclone Setup

# Configure rclone for your cloud provider
rclone config
# Choose: n) New remote
# Name: b2 (or s3, gcs, onedrive, etc.)
# Follow provider-specific setup

# Test
rclone lsd b2:
rclone mkdir b2:my-bucket/restic-repo

Initialize Restic Repository

# Local
export RESTIC_REPOSITORY=/mnt/backup/restic-repo
export RESTIC_PASSWORD="your-strong-password"
restic init

# Cloud (B2 example)
export RESTIC_REPOSITORY=b2:my-bucket/restic-repo
export B2_ACCOUNT_ID=your-account-id
export B2_ACCOUNT_KEY=your-account-key
export RESTIC_PASSWORD="your-strong-password"
restic init

Backup Script

#!/bin/bash
# /usr/local/bin/backup.sh

set -euo pipefail

export RESTIC_REPOSITORY=b2:my-bucket/restic-repo
export B2_ACCOUNT_ID=xxx
export B2_ACCOUNT_KEY=xxx
export RESTIC_PASSWORD="your-strong-password"

# Backup Docker volumes and configs
restic backup \
    /home/user/docker \
    /var/lib/docker/volumes \
    /etc/letsencrypt \
    --exclude-file=/etc/restic/excludes.txt \
    --tag "home-$(date +%Y%m%d)"

# Prune old snapshots
restic forget \
    --keep-daily 7 \
    --keep-weekly 4 \
    --keep-monthly 6 \
    --keep-yearly 2 \
    --prune

# Check repository integrity (monthly)
if [ $(date +%d) -eq 01 ]; then
    restic check --read-data-subset=10%
fi

Exclude File

# /etc/restic/excludes.txt
*/cache/*
*/tmp/*
*/logs/*.log
*.pyc
__pycache__
*.sock
*.pid
node_modules/
.git/

Backing Up Docker Volumes

Method 1: Borg/Restic Direct (Recommended)

Back up /var/lib/docker/volumes directly. Borg/Restic handles deduplication efficiently.

Method 2: Container-Based Backup

Use a dedicated backup container for consistent snapshots:

version: '3.8'

services:
  backup:
    image: b3vis/borgmatic:latest
    container_name: backup
    restart: unless-stopped
    volumes:
      - /var/lib/docker/volumes:/volumes:ro
      - /home/user/docker:/docker:ro
      - /etc/letsencrypt:/letsencrypt:ro
      - ./borgmatic-config.yaml:/etc/borgmatic/config.yaml:ro
      - /mnt/backup:/mnt/backup
      - /root/.ssh:/root/.ssh:ro
    environment:
      - BORG_PASSPHRASE=your-passphrase
    # Run daily at 2 AM
    deploy:
      resources:
        limits:
          memory: 2G

Method 3: Per-Service Backup Containers

For databases, use specialized backup sidecars:

services:
  postgres:
    image: postgres:16
    volumes:
      - postgres-data:/var/lib/postgresql/data

  postgres-backup:
    image: prodrigestivill/postgres-backup-local:14
    restart: unless-stopped
    volumes:
      - postgres-data:/var/lib/postgresql/data:ro
      - /mnt/backup/postgres:/backups
    environment:
      - POSTGRES_HOST=postgres
      - POSTGRES_DB=yourdb
      - POSTGRES_USER=youruser
      - POSTGRES_PASSWORD=yourpass
      - SCHEDULE=@daily
      - KEEP_DAYS=30

volumes:
  postgres-data:

Database Backups

Never rely solely on volume backups for databases. Use native dump tools for consistent, restorable backups.

PostgreSQL

# Inside container or via docker exec
pg_dump -U user -d dbname > backup.sql

# Compressed
pg_dump -U user -d dbname | gzip > backup.sql.gz

# Restore
gunzip -c backup.sql.gz | psql -U user -d dbname

MariaDB/MySQL

# Backup
mysqldump -u user -p dbname | gzip > backup.sql.gz

# All databases
mysqldump -u root -p --all-databases | gzip > all-dbs.sql.gz

# Restore
gunzip -c backup.sql.gz | mysql -u user -p dbname

Redis

# Trigger BGSAVE
redis-cli BGSAVE

# Copy RDB file
docker cp redis:/data/dump.rdb ./redis-backup-$(date +%Y%m%d).rdb

SQLite (Home Assistant, etc.)

# Use .backup command (safe for running DB)
sqlite3 /config/home-assistant_v2.db ".backup /backup/ha-$(date +%Y%m%d).db"

# Or use sqlite3 backup API via script

Budget Option: Friend's House / Second Location

# Sync to remote server via rsync/SSH
rsync -avz --delete /mnt/backup/ user@remote-server:/mnt/backup/

# Or use rclone with SFTP
rclone sync /mnt/backup/ sftp:remote:/backup/

Testing Your Restores

Untested backups are not backups. Schedule regular restore tests.

Monthly: Single File Restore

# Borg
borgmatic extract --archive latest --path docker/docker-compose.yml --destination /tmp/test-restore

# Restic
restic restore latest --target /tmp/test-restore --include docker/docker-compose.yml

Quarterly: Full Service Restore

  1. Spin up test server (VM, VPS, or spare hardware)
  2. Restore all Docker volumes and configs
  3. Deploy with docker compose
  4. Verify all services start and data is intact
  5. Document time taken and any issues

Annually: Disaster Recovery Drill

  1. Simulate total loss: wipe test server
  2. Reinstall OS, install Docker, restore everything
  3. Verify offsite backup accessibility
  4. Test with different hardware/cloud provider
  5. Update runbook with lessons learned

Restore Commands Reference

# Borg - list archives
borgmatic list --repository /mnt/backup/borg-repo

# Borg - extract specific archive
borgmatic extract --archive backup-2026-01-15T02:00:00 --destination /tmp/restore

# Restic - list snapshots
restic snapshots

# Restic - restore latest
restic restore latest --target /tmp/restore

# Restic - mount for browsing
restic mount /mnt/restic-mount
# Browse files, copy what you need
fusermount -u /mnt/restic-mount

Automation & Monitoring

Systemd Timers (Borgmatic)

# /etc/systemd/system/borgmatic-backup.service
[Unit]
Description=Borgmatic Backup
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/borgmatic --verbosity 1
Environment=BORG_PASSPHRASE=your-passphrase

# /etc/systemd/system/borgmatic-backup.timer
[Unit]
Description=Run Borgmatic daily

[Timer]
OnCalendar=daily
Persistent=true
RandomizedDelaySec=1h

[Install]
WantedBy=timers.target

Cron (Restic)

# /etc/cron.d/restic-backup
# Run daily at 2:30 AM
30 2 * * * root /usr/local/bin/backup.sh >> /var/log/restic-backup.log 2>&1

# Monthly check on 1st at 4 AM
0 4 1 * * root restic check --read-data-subset=10% >> /var/log/restic-check.log 2>&1

Monitoring with Healthchecks.io

# Add to backup script
curl -fsS --retry 3 https://hc-ping.com/your-uuid-here > /dev/null

# On failure, also ping failure endpoint
trap 'curl -fsS https://hc-ping.com/your-uuid-here/fail' ERR

Uptime Kuma Monitoring

Add a Push monitor in Uptime Kuma for each backup job. Set expected interval (e.g., 25 hours for daily). If backup doesn't push, you get alerted.

Backup Health Dashboard (Grafana)

Export backup metrics to Prometheus/Grafana:

# Borgmatic with Prometheus exporter
borgmatic --verbosity 1 --json > /var/log/borgmatic.json

# Parse with node_exporter textfile collector or custom script
