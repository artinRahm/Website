Home Assistant

Open-source home automation hub. Control 2000+ devices locally, no cloud required. Privacy-first automation with powerful scripting.

Beginner ~30 min read Updated 2026

Why Home Assistant?

Local Control

No internet required. Your automations run even when the cloud is down. Zero latency, total privacy.

2000+ Integrations

Zigbee, Z-Wave, Matter, Thread, Wi-Fi, Bluetooth, MQTT, Modbus, KNX, and every major smart home brand.

Powerful Automations

Visual editor, YAML, or Python scripts. Triggers, conditions, actions, blueprints, variables, parallel execution.

Voice Control

Built-in Assist (local voice), Alexa, Google Assistant, Siri shortcuts. Wake word detection with Wyoming protocol.

No Vendor Lock-in

Open source (MIT), runs on your hardware. Export data anytime. Community-driven, no subscription model.

Dashboards & Energy

Custom Lovelace dashboards, energy management, solar monitoring, device tracking, history graphs.

Installation Methods

Method Best For Pros Cons
Home Assistant OS (Recommended) Dedicated device (Pi, NUC, VM) Managed OS, auto-updates, add-ons, supervised Full device, no other apps
Home Assistant Container Existing Docker host Run alongside other containers, lightweight No add-ons, manual supervision
Home Assistant Supervised Debian/Ubuntu host Add-ons support, managed containers Specific OS requirements, complex
Home Assistant Core Developers, custom setups Maximum flexibility, pip install Manual everything, no add-ons
Recommendation: Use Home Assistant OS on a dedicated device (Raspberry Pi, Intel NUC, or VM). It's the easiest path with full add-on support and automatic updates.

Docker Deployment (Container Method)

Docker Compose

version: '3.8'

services:
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:2024.12
    container_name: homeassistant
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - homeassistant-config:/config
      - /etc/localtime:/etc/localtime:ro
      - /run/dbus:/run/dbus:ro
    ports:
      - "8123:8123"
    environment:
      - TZ=America/New_York
    # For USB devices (Zigbee/Z-Wave dongles):
    # devices:
    #   - /dev/ttyUSB0:/dev/ttyUSB0
    #   - /dev/ttyACM0:/dev/ttyACM0
    # privileged: true  # Alternative to devices
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8123/"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 60s

  # Optional: MQTT Broker
  mosquitto:
    image: eclipse-mosquitto:2
    container_name: mosquitto
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - mosquitto-data:/mosquitto/data
      - mosquitto-logs:/mosquitto/log
      - ./mosquitto/config:/mosquitto/config
    ports:
      - "1883:1883"
      - "9001:9001"

  # Optional: Zigbee2MQTT (if using Zigbee dongle)
  zigbee2mqtt:
    image: koenkk/zigbee2mqtt:latest
    container_name: zigbee2mqtt
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - zigbee2mqtt-data:/app/data
      - /run/udev:/run/udev:ro
    devices:
      - /dev/ttyUSB0:/dev/ttyUSB0  # Adjust to your dongle
    environment:
      - TZ=America/New_York

networks:
  homelab:
    external: true

volumes:
  homeassistant-config:
  mosquitto-data:
  mosquitto-logs:
  zigbee2mqtt-data:

Deploy

mkdir -p ~/homeassistant && cd ~/homeassistant
# Save as docker-compose.yml
docker compose up -d

# Check logs
docker compose logs -f homeassistant

Initial Setup

  1. Open http://your-server:8123
  2. Create owner account (first user = admin)
  3. Name your home, set location, unit system
  4. Home Assistant will auto-discover devices on network
  5. Finish setup → Dashboard loads

Configuration Basics

Configuration Structure

/config/
├── configuration.yaml      # Main config
├── automations.yaml        # Automations (or use UI)
├── scripts.yaml            # Scripts
├── scenes.yaml             # Scenes
├── dashboards/             # Lovelace dashboards
│   └── lovelace.yaml
├── secrets.yaml            # Passwords, tokens (gitignored)
├── packages/               # Modular config packages
├── themes/                 # Custom themes
├── www/                    # Static files (served at /local/)
├── custom_components/      # Custom integrations
└── .storage/               # UI-managed config (don't edit manually)

Essential Integrations

Network & Discovery

  • DHCP: Auto-discovers devices (enable in Settings → Devices & Services)
  • mDNS/Zeroconf: Finds HomeKit, Chromecast, printers
  • SSDP: UPnP devices (Sonos, Roku, etc.)
  • Network: Track device presence via ping/ARP

Protocol Integrations

MQTT

Core protocol for DIY sensors. Auto-discovery via homeassistant/ topic prefix.

Zigbee (via Zigbee2MQTT)

Inexpensive sensors, bulbs, switches. Sonoff, IKEA, Aqara, Tuya devices.

Z-Wave (via Z-Wave JS)

Reliable mesh, no hub needed. Aeotec, Zooz, Fibaro devices.

Matter/Thread

New unified standard. Border router required (HomePod, Google Nest, custom).

ESPHome

Custom ESP32/ESP8266 devices. Native HA API, OTA updates, deep sleep support.

Shelly

Wi-Fi relays, sensors. Local control, no cloud. Great for retrofits.

Cloud & Voice (Optional)

  • Nabu Casa Cloud: Remote access, Alexa/Google sync, supports HA development ($5/mo)
  • Assist (Local Voice): Settings → Voice Assistants → Add. Works offline with Wyoming.
  • Cloudflare Tunnel: Free secure remote access without open ports.

Automation Examples

Motion Light (YAML)

# automations.yaml
- alias: "Hallway Motion Light"
  trigger:
    - platform: state
      entity_id: binary_sensor.hallway_motion
      to: "on"
  condition:
    - condition: sun
      after: sunset
      after_offset: "-00:30:00"
    - condition: numeric_state
      entity_id: sensor.hallway_illuminance
      below: 50
  action:
    - service: light.turn_on
      target:
        entity_id: light.hallway
      data:
        brightness_pct: 80
        color_temp: 350
    - wait_for_trigger:
        - platform: state
          entity_id: binary_sensor.hallway_motion
          to: "off"
          for: "00:05:00"
    - service: light.turn_off
      target:
        entity_id: light.hallway
  mode: restart

Blueprints (Reusable Automations)

Settings → Automations → Blueprints → Import from forum/exchange. Popular: motion light, notify when door left open, sun-based climate.

Lovelace Dashboards

Dashboard Modes

  • Auto-generated: HA builds from entities (good start)
  • Manual (YAML): Full control, version control friendly
  • UI Editor: Drag-drop, card configuration

Essential Cards

title: Home
views:

    icon: mdi:home
    cards:

          - sensor.living_room_humidity

Backup & Restore

Built-in Backup (Home Assistant OS/Supervised)

Settings → System → Backups. Create full or partial backups. Schedule automatic backups to network storage.

Container Method Backup

#!/bin/bash
# /usr/local/bin/backup-homeassistant.sh
set -euo pipefail

BACKUP_DIR="/mnt/backups/homeassistant"
DATE=$(date +%F_%H-%M)
RETENTION_DAYS=30

mkdir -p "$BACKUP_DIR"

# Stop HA briefly for consistent backup (optional)
# docker stop homeassistant

# Backup config volume
docker run --rm \
  -v homeassistant-config:/config \
  -v "$BACKUP_DIR":/backup \
  alpine tar czf /backup/ha-config_$DATE.tar.gz -C /config .

# Start HA if stopped
# docker start homeassistant

# Cleanup
find "$BACKUP_DIR" -type f -mtime +$RETENTION_DAYS -delete

echo "Home Assistant backup completed: $DATE"

Restore

# 1. Stop container
docker compose down

# 2. Restore config
docker run --rm \
  -v homeassistant-config:/config \
  -v /mnt/backups/homeassistant:/backup \
  alpine tar xzf /backup/ha-config_2026-01-15_03-00.tar.gz -C /config

# 3. Start
docker compose up -d

Troubleshooting

Integration not showing up

# Check logs
docker logs homeassistant | grep -i "integration_name"

# Restart integration
# Settings → Devices & Services → Integration → Reload

# Clear browser cache / try incognito

Zigbee/Z-Wave dongle not detected

# Find device
ls -la /dev/ttyUSB* /dev/ttyACM*
# Note the device (e.g., /dev/ttyUSB0)

# Add to docker-compose.yml devices section
# Check permissions
ls -la /dev/ttyUSB0
# Should be accessible by container (run as root or add user to dialout group)

MQTT entities not appearing

# Check MQTT broker logs
docker logs mosquitto

# Verify discovery topic format
# homeassistant/sensor/unique_id/config
# Must include: name, unique_id, state_topic, device

# Enable MQTT debug in configuration.yaml:
# logger:
#   logs:
#     homeassistant.components.mqtt: debug

Automation not triggering

# Check trace in UI
# Settings → Automations → Your automation → Traces

# Test trigger manually
# Developer Tools → States → Set state to trigger value

# Check condition evaluation
# Use template editor: {{ states('binary_sensor.motion') }}

High memory / CPU usage

# Check recorder purge settings
# Increase purge frequency, reduce keep_days

# Disable unused integrations
# Settings → Devices & Services → Delete unused

# Limit history for noisy entities
# recorder:
#   exclude:
#     entities:
#       - sensor.noisy_sensor

# Check custom components for memory leaks

Reverse proxy issues (400/404 errors)

# Ensure HTTP config in configuration.yaml:
# http:
#   use_x_forwarded_for: true
#   trusted_proxies:
#     - 172.17.0.0/16

# Nginx Proxy Manager: Enable WebSocket Support
# Check X-Forwarded-For header passed correctly
