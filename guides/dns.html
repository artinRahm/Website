DNS & Local Domains

Set up Pi-hole or AdGuard Home for ad-blocking and local DNS. Use custom TLD for services. Split-horizon DNS for internal/external resolution.

Beginner ~20 min read Updated 2026

Why Local DNS?

Human-Readable Names

Access services via jellyfin.home.arpa instead of 192.168.1.50:8096.

Ad & Tracker Blocking

Pi-hole/AdGuard block ads network-wide. No client configuration needed.

Split-Horizon DNS

Internal IPs for local access, public IPs for remote. Same hostname, correct routing.

Certificate Validation

Let's Encrypt via DNS-01 challenge. Wildcard certs for *.home.arpa.

Choose Your DNS Solution

Feature Pi-hole AdGuard Home Technitium
UI/UX Functional, dated Modern, polished Advanced, complex
Ad Blocking Excellent (gravity) Excellent (built-in lists) Good
Local DNS (Custom Records) Local DNS tab DNS Rewrites Zone editor
DHCP Server Yes (optional) Yes Yes (full featured)
DoH/DoT/DoQ Via cloudflared Native Native
Client Groups/Policies Groups + adlists Client profiles Advanced policies
Resource Usage Low (PHP + FTL) Low (Go) Medium (Go + Web)
Recommendation: AdGuard Home for most users - modern UI, native DoH/DoT, easy setup. Pi-hole if you want mature community, gravity lists, or need DHCP. Technitium for power users needing full DNS server features.

AdGuard Home Deployment

Docker Compose

version: '3.8'

services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: adguardhome
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - adguard-work:/opt/adguardhome/work
      - adguard-conf:/opt/adguardhome/conf
    ports:
      - "53:53/tcp"      # DNS
      - "53:53/udp"      # DNS
      - "67:67/udp"      # DHCP (optional)
      - "68:68/tcp"      # DHCP (optional)
      - "80:80/tcp"      # HTTP (setup only)
      - "443:443/tcp"    # HTTPS (DoH)
      - "853:853/tcp"    # DoT
      - "3000:3000/tcp"  # Admin UI
    environment:
      - TZ=America/New_York
    cap_add:
      - NET_ADMIN  # For binding to port 53

networks:
  homelab:
    external: true

volumes:
  adguard-work:
  adguard-conf:

Deploy

mkdir -p ~/adguard && cd ~/adguard
# Save as docker-compose.yml
docker compose up -d

# Check logs
docker compose logs -f adguardhome

Initial Setup (Web UI)

  1. Open http://your-server:3000
  2. Port 53 check → "Use port 53" (if available)
  3. Admin username/password
  4. Finish → Dashboard loads

AdGuard Home Configuration

Upstream DNS (Encrypted)

Settings → DNS Settings → Upstream DNS Servers:

# DoH (DNS over HTTPS)
https://dns.google/dns-query
https://cloudflare-dns.com/dns-query
https://dns.quad9.net/dns-query

# DoT (DNS over TLS) - specify in DoT section
tls://dns.google
tls://1.1.1.1
tls://9.9.9.9

Enable "Bootstrap DNS" for initial resolution. Enable "Use upstream DNS servers concurrently" for speed.

Local DNS Records (DNS Rewrites)

Settings → DNS Rewrites → Add rewrite:

Domain Answer Description
jellyfin.home.arpa 10.10.10.10 Jellyfin server
nextcloud.home.arpa 10.10.10.11 Nextcloud
homeassistant.home.arpa 10.10.10.12 Home Assistant
portainer.home.arpa 10.10.10.13 Portainer
uptime.home.arpa 10.10.10.14 Uptime Kuma
auth.home.arpa 10.10.10.15 Authentik
*.home.arpa 10.10.10.10 Wildcard to reverse proxy

Blocklists

Settings → DNS Blocklists → Enable recommended:

  • AdGuard DNS filter
  • AdAway
  • OISD (combined, frequently updated)
  • HaGeZi Pro (multi-purpose)

Add custom: https://raw.githubusercontent.com/blocklistproject/Lists/master/ads.txt

Client Configuration

Settings → Client Configuration → Create profiles:

  • Default: All blocklists enabled
  • Kids: + Adult content blocklist, SafeSearch enforced
  • IoT: Minimal blocking (may break device updates)
  • Unfiltered: No blocking (for troubleshooting)

Assign clients by IP/MAC in "Clients" page.

Pi-hole Deployment (Alternative)

Docker Compose

version: '3.8'

services:
  pihole:
    image: pihole/pihole:latest
    container_name: pihole
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - pihole-etc:/etc/pihole
      - pihole-dnsmasq:/etc/dnsmasq.d
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "67:67/udp"      # DHCP
      - "80:80/tcp"      # Web UI
      - "443:443/tcp"    # HTTPS (optional)
    environment:
      - TZ=America/New_York
      - WEBPASSWORD_FILE=/run/secrets/pihole_password
      - DNS1=1.1.1.1
      - DNS2=8.8.8.8
      - CONDITIONAL_FORWARDING=1
      - CONDITIONAL_FORWARDING_DOMAIN=home.arpa
      - CONDITIONAL_FORWARDING_IP=10.10.10.1
    secrets:
      - pihole_password
    cap_add:
      - NET_ADMIN

networks:
  homelab:
    external: true

volumes:
  pihole-etc:
  pihole-dnsmasq:

secrets:
  pihole_password:
    file: ./secrets/pihole_password.txt

Local DNS (Custom.list)

# In Pi-hole container: /etc/pihole/custom.list
10.10.10.10  jellyfin.home.arpa

# Regenerate gravity
pihole restartdns reload-lists

Choosing a Local TLD

Recommended: .home.arpa (RFC 8375)

  • Reserved for home networks - never conflicts with public DNS
  • Supported by mDNS/DNS-SD (Bonjour, Avahi)
  • Works with Let's Encrypt DNS-01 (via ACME DNS)
  • Standard, future-proof

Alternatives

TLD Pros Cons
.local mDNS native, works out of box Conflict with .local TLD, not for authoritative DNS
.lan, .home, .internal Short, memorable Not reserved - could become public TLD
.home.arpa RFC reserved, standard Longer to type
Custom (homelab.internal) Full control, can delegate Must own domain, more complex

Split-Horizon DNS (Internal vs External)

Scenario

Same hostname resolves to:

  • Internal: jellyfin.example.com → 10.10.10.10 (LAN IP)
  • External: jellyfin.example.com → 203.0.113.5 (Public IP)

Implementation: AdGuard Home

Settings → DNS Rewrites - only applies to clients using AdGuard as DNS.

For public clients: Cloudflare/Route53 DNS records point to public IP.

Implementation: Cloudflare Tunnel + Split DNS

# cloudflared config.yml
tunnel: your-tunnel-id
credentials-file: /etc/cloudflared/creds.json
ingress:
  - hostname: jellyfin.example.com
    service: http://10.10.10.10:8096
  - hostname: nextcloud.example.com
    service: http://10.10.10.11:80
  - service: http_status:404

Internal clients use AdGuard (local IP). External clients hit Cloudflare → Tunnel → Service.

DHCP Integration

Option 1: Router Handles DHCP, AdGuard/Pi-hole for DNS

  • Router DHCP → Set DNS to AdGuard IP (10.10.10.5)
  • Simple, router manages leases
  • AdGuard sees all clients by IP

Option 2: AdGuard/Pi-hole Handles DHCP

  • Disable DHCP on router
  • AdGuard: Settings → DHCP → Enable, set range
  • Clients get hostname in AdGuard automatically
  • Better client identification in logs

Option 3: Kea DHCP (Advanced)

High-performance DHCP server. Integrates with AdGuard/Pi-hole via API for dynamic DNS updates.

Client Configuration

Automatic (DHCP)

Set DNS server in DHCP options to AdGuard/Pi-hole IP. All clients auto-configure.

Manual

OS Setting
Windows Settings → Network → DNS → Manual: 10.10.10.5
macOS System Settings → Network → DNS → + 10.10.10.5
Linux (systemd-resolved) DNS=10.10.10.5 in /etc/systemd/resolved.conf
iOS WiFi → ⓘ → Configure DNS → Manual → 10.10.10.5
Android WiFi → Modify → Advanced → DNS → 10.10.10.5

Encrypted DNS (DoH/DoT) on Clients

  • Firefox: Settings → Network Settings → Enable DNS over HTTPS → Custom: https://adguard.home.arpa/dns-query
  • Chrome: chrome://flags/#dns-over-https → Custom: https://adguard.home.arpa/dns-query
  • iOS/macOS: Profile with DoH template

Troubleshooting

DNS not resolving

# Test from client
nslookup jellyfin.home.arpa 10.10.10.5
dig @10.10.10.5 jellyfin.home.arpa

# Test upstream
dig @1.1.1.1 google.com

# Check AdGuard logs
docker logs adguardhome | grep -i error

Slow DNS resolution

# Enable parallel upstream queries
# Reduce blocklist count
# Check upstream latency: dig @1.1.1.1 google.com +stats
# Consider local unbound recursive resolver

Local hostnames not resolving

# Verify DNS rewrites / custom.list entries
# Check for typos (trailing dots, case sensitivity)
# Flush client DNS cache:
# Windows: ipconfig /flushdns
# macOS: sudo dscacheutil -flushcache
# Linux: systemd-resolve --flush-caches

Port 53 conflicts

# Check what's on port 53
ss -ulpn | grep :53
# systemd-resolved often binds 127.0.0.53:53
# Disable: systemctl disable --now systemd-resolved
# Or change AdGuard port to 5353, use iptables redirect

Android "Private DNS" bypassing AdGuard

# Android 9+ uses DoT by default
# Settings → Network → Private DNS → Off
# Or set to: adguard.home.arpa (if DoT enabled on AdGuard)
