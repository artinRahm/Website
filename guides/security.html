Security Hardening

Fail2ban, SSH keys only, 2FA on everything, regular updates, minimal attack surface. Defense in depth for your home lab.

Intermediate ~30 min read Updated 2026

Security Principles

Defense in Depth

Multiple layers: network, host, application, data. No single point of failure.

Least Privilege

Users/services get minimum access needed. No root where not required.

Minimal Attack Surface

Disable unused services, close unused ports, uninstall unneeded packages.

Assume Breach

Design for detection and containment. Logging, monitoring, incident response ready.

SSH Hardening

/etc/ssh/sshd_config

# Network
Port 22
AddressFamily any
ListenAddress 0.0.0.0
ListenAddress ::

# Authentication
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no
UsePAM yes

# Key types (modern only)
PubkeyAcceptedKeyTypes ssh-ed25519,ssh-ed25519-cert-v01@openssh.com,ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521
HostKeyAlgorithms ssh-ed25519,ssh-ed25519-cert-v01@openssh.com,ecdsa-sha2-nistp256,ecdsa-sha2-nistp384,ecdsa-sha2-nistp521

# Ciphers & MACs (modern only)
Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes192-ctr,aes128-ctr
MACs hmac-sha2-256-etm@openssh.com,hmac-sha2-512-etm@openssh.com,umac-128-etm@openssh.com
KexAlgorithms curve25519-sha256,curve25519-sha256@libssh.org,diffie-hellman-group-exchange-sha256

# Security
MaxAuthTries 3
MaxSessions 2
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2
PermitEmptyPasswords no
PermitUserEnvironment no
AllowAgentForwarding no
AllowTcpForwarding no
X11Forwarding no
PrintMotd no
Banner /etc/ssh/banner

# Logging
SyslogFacility AUTH
LogLevel VERBOSE

# Access control (adjust for your network)
AllowUsers admin@10.10.10.0/24 admin@10.10.50.0/24
# Or use AllowGroups sshusers

Generate Ed25519 Keys

# On client machine
ssh-keygen -t ed25519 -a 100 -C "your-email@domain.com"
# -a 100 = 100 KDF rounds (more secure)

# Copy to server
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server

# Test
ssh -o PreferredAuthentications=publickey user@server

SSH Certificate Authority (Advanced)

# Generate CA key
ssh-keygen -t ed25519 -f ssh_ca -C "home-lab-ca"

# Sign user keys (valid 1 day)
ssh-keygen -s ssh_ca -I "user@laptop" -n admin -V +1d ~/.ssh/id_ed25519.pub

# Server config: TrustedUserCAKeys /etc/ssh/ssh_ca.pub
# Client config: CertificateFile ~/.ssh/id_ed25519-cert.pub

Two-Factor Authentication (2FA)

SSH with TOTP

# Install
sudo apt install libpam-google-authenticator

# Configure per user
google-authenticator
# Answer: y, y, y, n, y (time-based, disallow reuse, rate limit)

# /etc/pam.d/sshd - add at TOP
auth required pam_google_authenticator.so nullok

# /etc/ssh/sshd_config
AuthenticationMethods publickey,keyboard-interactive
ChallengeResponseAuthentication yes
UsePAM yes

2FA for Web Services

Service 2FA Method Setup
Authentik TOTP, WebAuthn, Email, SMS, Duo Flows → Add Authenticator Validation stage
Home Assistant TOTP (built-in) Profile → Enable MFA
Nextcloud TOTP, WebAuthn, U2F Settings → Security → 2FA
Portainer OIDC/LDAP (via Authentik) Settings → Authentication
Grafana OIDC (via Authentik) Configure generic_oauth with Authentik
Uptime Kuma TOTP (built-in) Settings → Account → Enable 2FA

Hardware Keys (WebAuthn / FIDO2)

  • YubiKey, SoloKey, Nitrokey, Apple TouchID, Windows Hello
  • Phishing-resistant - domain bound
  • Register multiple keys (backup)
  • Authentik: Settings → Authenticator Types → Enable WebAuthn

Intrusion Prevention (Fail2ban / CrowdSec)

Fail2ban (Traditional)

# Install
sudo apt install fail2ban

# /etc/fail2ban/jail.local
[DEFAULT]
bantime = 1h
findtime = 10m
maxretry = 3
backend = systemd
banaction = ufw
ignoreip = 127.0.0.1/8 10.10.10.0/24 10.10.50.0/24

[sshd]
enabled = true
port = ssh
filter = sshd
logpath = %(sshd_log)s
maxretry = 3

[nginx-http-auth]
enabled = true
filter = nginx-http-auth
port = http,https
logpath = /var/log/nginx/error.log

[nginx-botsearch]
enabled = true
filter = nginx-botsearch
port = http,https
logpath = /var/log/nginx/access.log
maxretry = 2

[docker]
enabled = true
filter = docker
port = 2376,2375
logpath = /var/log/docker.log

Custom Filters

# /etc/fail2ban/filter.d/nginx-404.conf
[Definition]
failregex = ^ -.*"(GET|POST).*HTTP.*" 404
ignoreregex =

# /etc/fail2ban/filter.d/traefik-auth.conf
[Definition]
failregex = ^.*"remote_addr":"".*"status":401.*
ignoreregex =

Automated Updates

OS Package Updates

# Ubuntu/Debian - unattended-upgrades
sudo apt install unattended-upgrades apt-listchanges

# /etc/apt/apt.conf.d/50unattended-upgrades
Unattended-Upgrade::Allowed-Origins {
    "${distro_id}:${distro_codename}-security";
    "${distro_id}:${distro_codename}-updates";
    "${distro_id}ESMApps:${distro_codename}-apps-security";
    "${distro_id}ESM:${distro_codename}-infra-security";
};
Unattended-Upgrade::AutoFixInterruptedDpkg "true";
Unattended-Upgrade::MinimalSteps "true";
Unattended-Upgrade::Remove-Unused-Dependencies "true";
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "03:00";

# /etc/apt/apt.conf.d/20auto-upgrades
APT::Periodic::Update-Package-Lists "1";
APT::Periodic::Download-Upgradeable-Packages "1";
APT::Periodic::AutocleanInterval "7";
APT::Periodic::Unattended-Upgrade "1";

Docker Image Updates

# Watchtower - auto-update containers
version: '3.8'
services:
  watchtower:
    image: containrrr/watchtower:latest
    container_name: watchtower
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      - WATCHTOWER_SCHEDULE=0 0 4 * * *  # Daily 4 AM
      - WATCHTOWER_CLEANUP=true
      - WATCHTOWER_INCLUDE_RESTARTING=true
      - WATCHTOWER_LABEL_ENABLE=true  # Only update labeled containers
      - WATCHTOWER_NOTIFICATION_EMAIL_FROM=watchtower@home.arpa
      - WATCHTOWER_NOTIFICATION_EMAIL_TO=admin@home.arpa
      - WATCHTOWER_NOTIFICATION_EMAIL_SERVER=smtp.home.arpa
      - WATCHTOWER_NOTIFICATION_EMAIL_SERVER_PORT=587
    labels:
      - com.centurylinklabs.watchtower.enable=true

networks:
  homelab:
    external: true

      - PASSWORD=

Incident Response Preparation

Backup Verification

# Monthly restore test
#!/bin/bash
# test-restore.sh
set -euo pipefail
BACKUP_DIR="/mnt/backups"
TEST_DIR="/tmp/restore-test-$(date +%s)"

# Test each service backup
for service in jellyfin nextcloud homeassistant; do
    latest=$(ls -t $BACKUP_DIR/${service}_*.tar.gz | head -1)
    echo "Testing $latest"
    mkdir -p $TEST_DIR/$service
    tar xzf $latest -C $TEST_DIR/$service
    # Verify key files exist
    [ -f $TEST_DIR/$service/config.yaml ] || exit 1
done
echo "All backups verified"
rm -rf $TEST_DIR

Hardening Checklist

Network

  • ☐ VLANs segmented with firewall rules
  • ☐ Default deny inbound on all interfaces
  • ☐ VPN for all remote access
  • ☐ No direct port forwards to services
  • ☐ GeoIP blocking on edge
  • ☐ mDNS/SSDP blocked between VLANs

Host

  • ☐ SSH: keys only, no passwords, no root
  • ☐ 2FA on SSH (TOTP or FIDO2)
  • ☐ UFW/nftables enabled, default deny
  • ☐ Unattended security updates enabled
  • ☐ Fail2ban/CrowdSec running
  • ☐ Auditd for critical file changes

Services

  • ☐ All services behind reverse proxy
  • ☐ Authentik SSO + 2FA for all apps
  • ☐ No default passwords anywhere
  • ☐ Containers run as non-root
  • ☐ Read-only root filesystem where possible
  • ☐ Resource limits on all containers

Data & Secrets

  • ☐ Encrypted backups, tested monthly
  • ☐ Secrets in Docker secrets / SOPS / Vaultwarden
  • ☐ No secrets in git / Docker images
  • ☐ TLS everywhere (internal + external)
  • ☐ Certificate monitoring (expiry alerts)
  • ☐ Key rotation schedule documented

Monitoring

  • ☐ Uptime Kuma monitoring all services
  • ☐ Log aggregation (Loki/ELK)
  • ☐ Alerting on anomalies
  • ☐ Weekly log review
  • ☐ Vulnerability scanning (Trivy) weekly
  • ☐ Lynis audit monthly

Operations

  • ☐ Documented incident response plan
  • ☐ Offline backup of configs/secrets
  • ☐ Console/serial access to all hosts
  • ☐ Change management for firewall rules
  • ☐ Quarterly security review
  • ☐ Threat model updated annually

Troubleshooting

Locked out after SSH hardening

# Console/serial access required
# Check sshd config syntax
sshd -t

# Check logs
journalctl -u ssh -f

# Temporarily allow password from console
# sed -i 's/PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config
# systemctl reload ssh

2FA not working

# Check time sync (critical for TOTP)
timedatectl status
# Install chrony/ntpd if drifting

# Verify PAM config
# /etc/pam.d/sshd - google-authenticator line at TOP
# Check sshd_config: ChallengeResponseAuthentication yes

Fail2ban not banning

# Check filter matches
fail2ban-regex /var/log/auth.log /etc/fail2ban/filter.d/sshd.conf

# Check jail status
fail2ban-client status sshd

# Verify backend (systemd vs pyinotify)
# Check ignoreip not matching attacker

Container escaping / privilege escalation

# Check for privileged containers
docker ps --filter "status=running" --format "{{.Names}}: {{.HostConfig.Privileged}}"

# Check capabilities
docker inspect container | grep -A 20 CapAdd

# Run security scan
trivy image --severity HIGH,CRITICAL image:name

Certificate expired

# Check all certs
find /etc -name "*.crt" -o -name "*.pem" | xargs -I {} \
  openssl x509 -in {} -noout -text | grep -E "Subject:|Not After"

# Automate with certbot / step-ca / Traefik ACME
# Alert 30 days before expiry (Uptime Kuma can monitor)
