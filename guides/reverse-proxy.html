Reverse Proxy & SSL

Set up Nginx Proxy Manager with automatic Let's Encrypt SSL certificates. Single entry point, automatic HTTPS, and easy service management for your entire home lab.

Beginner ~20 min read Updated 2026

Why Use a Reverse Proxy?

A reverse proxy sits between the internet and your services, forwarding requests to the appropriate backend. For home labs, it's essential.

Single Port Exposure

Only open ports 80 & 443 on your router. All services accessible via subdomains (jellyfin.yourdomain.com) or paths (yourdomain.com/jellyfin).

Automatic HTTPS

Let's Encrypt integration provides free, valid SSL certificates with auto-renewal. No more browser warnings or manual cert management.

Service Discovery

Easy to add new services. Just add a proxy host entry - no port forwarding changes needed.

Security Features

Rate limiting, IP blocking, basic auth, header manipulation, WebSocket support - all configurable via UI.

Reverse Proxy Options

Solution UI Auto SSL Learning Curve Best For
Nginx Proxy Manager ✅ Beautiful Web UI ✅ Built-in Let's Encrypt Low Most home labs - recommended
Traefik ✅ Dashboard ✅ Built-in Medium Docker Swarm/Kubernetes, dynamic configs
Caddy ❌ Config file only ✅ Automatic by default Low Simple setups, config-as-code
HAProxy ❌ Stats page only ❌ Manual High High performance, enterprise
Manual Nginx ❌ Config files ❌ Manual certbot High Full control, learning Nginx
Recommendation: Start with Nginx Proxy Manager (NPM). It has the best balance of features, ease of use, and community support for home labs.

Nginx Proxy Manager Setup

Prerequisites

  • A domain name (or free subdomain from DuckDNS, No-IP, etc.)
  • Ports 80 and 443 forwarded on your router to your server
  • Docker and Docker Compose installed

Docker Compose

version: '3.8'

services:
  npm:
    image: 'jc21/nginx-proxy-manager:latest'
    container_name: nginx-proxy-manager
    restart: unless-stopped
    ports:
      - '80:80'      # HTTP for Let's Encrypt validation
      - '443:443'    # HTTPS
      - '81:81'      # Admin UI
    volumes:
      - ./data:/data
      - ./letsencrypt:/etc/letsencrypt
    networks:
      - homelab

networks:
  homelab:
    driver: bridge
    external: true

Deploy

# Create directory and compose file
mkdir -p ~/npm && cd ~/npm
# Save the above as docker-compose.yml

# Start
docker compose up -d

# Verify
docker compose logs -f npm

Initial Configuration

  1. Open http://your-server-ip:81 in browser
  2. Default login: admin@example.com / changeme
  3. Immediately change email and password on first login
  4. Go to Settings → Users to add more admins if needed

Automatic SSL with Let's Encrypt

How It Works

Let's Encrypt validates domain ownership via HTTP-01 challenge (port 80) or DNS-01 challenge (DNS TXT record). NPM handles this automatically.

HTTP-01 Challenge (Standard)

Requires port 80 open to the internet. Easiest setup.

  1. In NPM, go to SSL Certificates → Add SSL Certificate → Let's Encrypt
  2. Enter your domain(s): yourdomain.com, *.yourdomain.com (wildcard)
  3. Enable Use DNS Challenge only if using DNS-01
  4. Enter your email for expiration notices
  5. Agree to Let's Encrypt ToS
  6. Click Save - NPM handles validation and issuance

DNS-01 Challenge (For Wildcards / No Port 80)

Required for wildcard certificates (*.yourdomain.com) or if port 80 is blocked.

  1. Get API credentials from your DNS provider (Cloudflare, GoDaddy, Namecheap, etc.)
  2. In NPM: SSL Certificates → Add SSL Certificate → Let's Encrypt
  3. Enable Use DNS Challenge
  4. Select your DNS provider
  5. Enter API credentials
  6. Save - NPM creates TXT records automatically
Cloudflare setup: Create API token with "Zone > DNS > Edit" permissions. Use "Global API Key" if token doesn't work. Never commit credentials to git!

Force HTTPS & HSTS

In NPM proxy host settings:

  • Force SSL - Redirects HTTP to HTTPS
  • HSTS Enabled - Tells browsers to always use HTTPS (include subdomains)
  • HSTS Subdomains - Apply to all subdomains

Adding Your Services

Subdomain vs Path Routing

Method Example Pros Cons
Subdomain jellyfin.yourdomain.com Clean URLs, better isolation, cookie separation Requires wildcard cert or multiple certs
Path yourdomain.com/jellyfin Single cert, works with any domain Cookie conflicts, some apps break
Use subdomains. They're cleaner, more secure (cookie isolation), and work better with modern web apps. Get a wildcard cert with DNS challenge.

Adding a Proxy Host (Subdomain)

  1. In NPM: Proxy Hosts → Add Proxy Host
  2. Domain Names: jellyfin.yourdomain.com
  3. Scheme: http (usually - backend talks HTTP)
  4. Forward Hostname/IP: jellyfin (container name) or 172.20.0.5 (container IP)
  5. Forward Port: 8096 (Jellyfin's internal port)
  6. Block Common Exploits: ✅ On
  7. Websockets Support: ✅ On (required for Jellyfin, Home Assistant, etc.)
  8. Access List: Optional - restrict by IP or add auth
  9. SSL tab: Select your Let's Encrypt certificate
  10. Enable Force SSL, HSTS Enabled, HSTS Subdomains
  11. Save

Common Service Configurations

Jellyfin

Forward Host: jellyfin
Forward Port: 8096
Websockets: ✅ On
Custom locations: (usually none needed)

Nextcloud

Forward Host: nextcloud
Forward Port: 80
Websockets: ✅ On
Custom: proxy_set_header X-Forwarded-Proto https;

Home Assistant

Forward Host: homeassistant
Forward Port: 8123
Websockets: ✅ On (critical!)
Add: proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";

Portainer

Forward Host: portainer
Forward Port: 9000
Websockets: ✅ On
SSL: Use your Let's Encrypt cert

Custom Nginx Configuration (Advanced)

In proxy host → Advanced tab, add custom config:

# Increase upload size for Nextcloud
client_max_body_size 10G;

# WebSocket support
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 86400;

# Security headers
add_header X-Frame-Options "SAMEORIGIN";
add_header X-Content-Type-Options "nosniff";
add_header Referrer-Policy "strict-origin-when-cross-origin";

# Cache static assets
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}

Advanced Configuration

Access Lists (Authentication)

Add basic auth or IP restrictions to sensitive services:

  1. NPM: Access Lists → Add Access List
  2. Name it (e.g., "Admin Only")
  3. Type: HTTP Basic Auth
  4. Add users with htpasswd generated passwords
  5. Or Type: IP Allow List for IP restrictions
  6. Apply to proxy host → Access List dropdown
# Generate htpasswd entry
docker run --rm httpd:alpine htpasswd -nbB admin 'your-password'
# Output: admin:$2y$05$abcdef...
# Use the full hash in NPM

Redirection Hosts

Redirect old domains or www to non-www:

  1. Redirection Hosts → Add Redirection Host
  2. Domain: www.yourdomain.com
  3. Forward to: https://yourdomain.com
  4. Enable Preserve Path
  5. Select SSL certificate

Stream (TCP/UDP) Proxies

For non-HTTP services (game servers, databases, etc.):

  1. Stream → Add Stream
  2. Incoming port: 25565 (Minecraft)
  3. Forward to: minecraft-server:25565
  4. TCP/UDP as needed

Multiple NPM Instances (HA)

For high availability, run 2+ NPM instances with shared /data and /etc/letsencrypt volumes (use NFS or replicated storage). Put behind a load balancer.

Troubleshooting

502 Bad Gateway

NPM can't reach backend service

# Check container is running
docker ps | grep jellyfin

# Check network connectivity
docker exec nginx-proxy-manager ping jellyfin

# Verify port
docker exec nginx-proxy-manager wget -qO- http://jellyfin:8096

SSL Certificate Fails

Let's Encrypt validation fails

# Check port 80 accessibility
curl -I http://yourdomain.com

# Check DNS resolves correctly
dig yourdomain.com

# Check NPM logs
docker logs nginx-proxy-manager | grep -i acme

WebSocket Not Working

Home Assistant, Jellyfin live TV, etc. fail

# In Advanced tab, ensure:
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_read_timeout 86400;
# And in proxy host: Websockets Support = ON

Too Many Redirects

HTTPS redirect loop

# Check service isn't also forcing HTTPS
# In NPM: Force SSL = ON
# In service config: Disable HTTPS redirect
# Ensure X-Forwarded-Proto header passed

Large File Uploads Fail

Nextcloud, file uploads timeout

# In Advanced tab:
client_max_body_size 10G;
proxy_request_buffering off;

Certificate Not Renewing

Let's Encrypt cert expired

# Check cron in container
docker exec nginx-proxy-manager crontab -l

# Force renewal
docker exec nginx-proxy-manager /usr/bin/certbot renew --force-renewal

# Check logs
docker logs nginx-proxy-manager | grep -i renew
