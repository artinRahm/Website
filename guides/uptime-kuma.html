Uptime Kuma

Self-hosted monitoring with beautiful status pages. HTTP(s), TCP, DNS, Docker, and push monitoring. Multiple notification channels.

Beginner ~15 min read Updated 2026

Why Uptime Kuma?

Multiple Monitor Types

HTTP(s), TCP, Ping, DNS, Push, Steam Game Server, Docker containers, and more.

Beautiful Status Pages

Public status pages with custom domains, branding, incident timeline. Like statuspage.io but free.

50+ Notification Channels

Telegram, Discord, Slack, Email, Pushover, Gotify, Matrix, Webhook, PagerDuty, Opsgenie, and more.

Certificate Monitoring

SSL/TLS certificate expiry alerts. Track expiration dates, auto-renewal status.

Docker Monitoring

Monitor container health, auto-discover containers, track resource usage.

Lightweight & Fast

Node.js + SQLite. Low resource usage. Runs on Raspberry Pi. Easy backup (single file).

Docker Deployment

Docker Compose

version: '3.8'

services:
  uptime-kuma:
    image: louislam/uptime-kuma:1.23
    container_name: uptime-kuma
    restart: unless-stopped
    networks:
      - homelab
    volumes:
      - uptime-kuma-data:/app/data
    ports:
      - "3001:3001"
    environment:
      - TZ=America/New_York
    # Optional: Run as non-root (UID 1000)
    # user: "1000:1000"

networks:
  homelab:
    external: true

volumes:
  uptime-kuma-data:

Deploy

mkdir -p ~/uptime-kuma && cd ~/uptime-kuma
# Save as docker-compose.yml
docker compose up -d

# Check logs
docker compose logs -f uptime-kuma

Initial Setup

  1. Open http://your-server:3001
  2. Create admin account (username/password)
  3. Dashboard loads - ready to add monitors

Monitor Types & Configuration

HTTP(s) Monitor

Most common - checks web services, APIs, websites.

  • URL: Full URL including protocol
  • Method: GET, POST, PUT, etc.
  • Expected Status: 200-299, or specific code
  • Headers: Custom headers (auth tokens, API keys)
  • Body: For POST requests
  • Keyword: Check response contains specific text
  • Max Redirects: Follow redirects (default 10)
  • Accept Invalid Certs: For self-signed certs

TCP Port Monitor

Check if a port is open (databases, game servers, custom services).

  • Hostname/IP + Port
  • Optional: Send string, expect string in response

DNS Monitor

Verify DNS resolution returns expected IP.

  • Domain name + expected IP
  • Record type: A, AAAA, CNAME, MX, TXT
  • Custom DNS server (default: system)

Push Monitor

For cron jobs, backups, scripts - they "push" status to Uptime Kuma.

  1. Create Push monitor → get push URL
  2. In your script: curl -X POST "https://uptime.yourdomain.com/api/push/abc123?status=up&msg=OK&ping=45"
  3. If no push received within interval → DOWN

Docker Monitor

Monitor container health checks automatically.

  • Select Docker host (local or remote)
  • Choose container to monitor
  • Uses container's HEALTHCHECK

Steam Game Server

Query Steam game servers (CS2, TF2, Valheim, etc.) for player count, map, status.

Telegram Setup Example

  1. Message @BotFather → /newbot
  2. Copy bot token
  3. Message @userinfobot → get chat ID
  4. In Uptime Kuma: Notifications → Add → Telegram
  5. Paste token and chat ID
  6. Test notification

Notification Groups

Group multiple channels. Assign groups to monitors. Different groups for critical vs. informational.

Status Pages

Create a Public Status Page

  1. Status Pages → New Status Page
  2. Slug: status (accessible at https://uptime.yourdomain.com/status)
  3. Title: "My Services Status"
  4. Select monitors to display
  5. Custom domain: Add CNAME, enable in settings
  6. Customize: Logo, colors, footer, custom CSS

Status Page Features

  • Real-time monitor status
  • Incident timeline (auto from downtime)
  • 90-day uptime percentage
  • Response time graphs
  • Maintenance windows (planned downtime)
  • RSS/Atom feed for subscribers
  • Password protection option

Advanced Configuration

Reverse Proxy with SSL

Using Nginx Proxy Manager (see Reverse Proxy Guide):

  1. Add proxy host: uptime.yourdomain.com
  2. Forward to: uptime-kuma:3001
  3. Enable WebSocket support (required for real-time updates)
  4. SSL: Let's Encrypt, Force SSL, HSTS

Two-Factor Authentication (2FA)

Settings → Account → Enable 2FA (TOTP). Scan QR with Authenticator app.

Backup & Restore

# Backup (single SQLite file)
cp /path/to/uptime-kuma/data/kuma.db /backups/uptime-kuma-$(date +%F).db

# Or via Docker
docker run --rm \
  -v uptime-kuma-data:/app/data \
  -v $(pwd):/backup \
  alpine cp /app/data/kuma.db /backup/kuma-$(date +%F).db

# Restore
docker run --rm \
  -v uptime-kuma-data:/app/data \
  -v $(pwd):/backup \
  alpine cp /backup/kuma-2026-01-15.db /app/data/kuma.db

Multiple Docker Hosts

Settings → Docker → Add Docker Host. Supports TCP (with TLS) or Unix socket via SSH tunnel.

Maintenance Windows

Schedule planned downtime. Monitors in maintenance won't trigger alerts.

Troubleshooting

Monitor shows DOWN but service works

# Check from Uptime Kuma container
docker exec uptime-kuma curl -v https://your-service.com

# Check DNS resolution
docker exec uptime-kuma nslookup your-service.com

# Verify network connectivity
docker exec uptime-kuma ping your-service.com

Notifications not sending

# Check notification test in UI
# Check container logs for errors
docker logs uptime-kuma | grep -i notification

# Verify webhook URL accessible from container
docker exec uptime-kuma curl -X POST "your-webhook-url"

Real-time updates not working

# Ensure WebSocket support in reverse proxy
# Nginx Proxy Manager: Enable "WebSocket Support"
# Check browser console for WS connection errors

High memory usage

# Limit data retention
# Settings → General → Monitoring History: 30 days (default 90)
# Reduce heartbeat interval for less frequent checks
